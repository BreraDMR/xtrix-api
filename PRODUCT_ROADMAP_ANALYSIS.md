## 1️⃣ ВИЗИЯ ПРОДУКТА

### ✅ Что есть:
- Базовая CRM-платформа для сферы услуг
- Разделение на специалистов и клиентов (роли: admin, specialist, client)
- Поддержка многоязычности (EN, RU, CZ)
- Мобильное приложение (Flutter)

### ❌ Чего нет:
- Явной поддержки разных типов специалистов (массажист, косметолог, врач и т.д.)
- Разделения на beauty/wellness/здравоохранение на уровне системы
- Глобального клиентского аккаунта (один клиент для всех специалистов)

### 🔧 Как реализовать:
1. **Добавить поле `specialist_type` в модель `User`** (массажист, косметолог, терапевт и т.д.)
2. **Создать модель `SpecialistProfile`** с расширенной информацией:
   - Тип специалиста (enum: beauty, wellness, healthcare)
   - Подтип (массажист, косметолог, стоматолог и т.д.)
   - Специализация
3. **Реализовать глобальный клиентский аккаунт:**
   - Отделить `Client` от `owner_id` (убрать жесткую привязку)
   - Создать модель `ClientSpecialistRelation` для связи клиента с несколькими специалистами
   - Добавить глобальный `client_id` который может использоваться разными специалистами

**Приоритет:** Высокий (ключевое конкурентное преимущество)  
**Сложность:** Средняя-Высокая

## 3️⃣ РОЛИ В СИСТЕМЕ

### ✅ Что есть:
- ✅ Специалист (specialist role):
  - ✅ Управление клиентами (`/clients/`)
  - ✅ Процедуры (`/services/`, `/visits/`)
  - ✅ Календарь (calendar endpoint, SimpleCalendar component)
  - ✅ Финансы (analytics, financial reports)
  - ❌ Сотрудники (нет управления сотрудниками)
- ✅ Клиент (client role):
  - ✅ Базовая структура роли
  - ❌ Личный аккаунт (нет клиентского интерфейса)
  - ❌ История процедур (нет отдельного endpoint для клиента)
  - ❌ Список специалистов
  - ❌ Бронирование (нет публичного API)
- ✅ Администратор платформы (admin role):
  - ✅ Управление пользователями (`/users/`)
  - ✅ Управление лицензиями (`/subscriptions/`)
  - ✅ Аналитика (`/analytics/`)
  - ❌ Модерация аккаунтов (частично есть через unlock, но нет полной модерации)

### ❌ Чего нет:
1. **Клиентский интерфейс:**
   - Отдельный фронтенд/мобильное приложение для клиентов
   - Публичные API endpoints для клиентов
   - Авторизация через QR-код (есть QR-код, но нет полноценной авторизации)

2. **Управление сотрудниками:**
   - Нет модели Employee/Staff
   - Нет связи между специалистом и его сотрудниками
   - Нет распределения клиентов между сотрудниками

3. **Модерация:**
   - Нет системы модерации аккаунтов
   - Нет бана/блокировки специалистов администратором платформы

### 🔧 Как реализовать:

#### 3.1 Клиентский интерфейс:
1. **Создать отдельное мобильное приложение для клиентов** (или разделить текущее)
2. **Добавить публичные API endpoints:**
   - `GET /clients/me/visits` - история процедур клиента
   - `GET /clients/me/specialists` - список специалистов клиента
   - `POST /public/bookings` - публичное бронирование
3. **Реализовать авторизацию через QR-код** (уже есть база в `qr_code.py`)

#### 3.2 Управление сотрудниками:
1. **Создать модель `Employee`:**
   ```python
   class Employee(Base):
       id = Column(Integer, primary_key=True)
       specialist_id = Column(Integer, ForeignKey("users.id"))  # владелец
       user_id = Column(Integer, ForeignKey("users.id"))  # сотрудник
       role = Column(String)  # manager, employee
       permissions = Column(JSON)  # права доступа
   ```
2. **Добавить endpoints:**
   - `POST /employees/` - нанять сотрудника
   - `GET /employees/` - список сотрудников
   - `PUT /employees/{id}/permissions` - управление правами

#### 3.3 Модерация:
1. **Расширить модель `User`:**
   - `is_verified = Column(Boolean)`
   - `moderation_status = Column(String)` (pending, approved, rejected, banned)
   - `moderation_notes = Column(Text)`
2. **Добавить endpoints:**
   - `POST /admin/users/{id}/moderate` - модерация аккаунта
   - `GET /admin/users/pending` - список на модерации

**Приоритет:** Высокий (клиентский интерфейс), Средний (сотрудники, модерация)  
**Сложность:** Высокая (клиентский интерфейс), Средняя (остальное)
