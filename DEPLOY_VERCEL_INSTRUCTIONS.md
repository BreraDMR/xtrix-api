# 📦 Инструкция по развертыванию на Vercel

## 🚀 Способ 1: Развертывание через веб-интерфейс (самый простой)

### Шаг 1: Подготовка
Убедитесь, что вы находитесь в папке `frontend`:
```powershell
cd frontend
```

### Шаг 2: Вход на Vercel
1. Откройте сайт: **https://vercel.com/**
2. Нажмите **"Sign Up"** или **"Log In"**
   - Можно войти через GitHub (удобно, если аккаунт уже привязан)

### Шаг 3: Создание проекта
1. После входа нажмите **"Add New..."** → **"Project"**
2. Нажмите **"Import Git Repository"**
3. Выберите ваш репозиторий **BooNaty/Xtrix**

### Шаг 4: Настройка проекта

**В разделе "Configure Project":**

1. **Root Directory**: 
   - Нажмите **"Edit"** рядом с "Root Directory"
   - Введите: `frontend`
   - Это говорит Vercel, что проект находится в папке `frontend`

2. **Framework Preset**: 
   - Должен автоматически определить **Vite**
   - Если нет, выберите **"Vite"** вручную

3. **Build Command**: 
   - Оставьте: `npm run build`

4. **Output Directory**: 
   - Оставьте: `dist`

5. **Install Command**: 
   - Оставьте: `npm install`

### Шаг 5: Переменные окружения (Environment Variables)

**В разделе "Environment Variables" добавьте:**

- **Key**: `VITE_API_BASE_URL`
- **Value**: `http://localhost:8000` (для локального бэкенда)
  - Или URL вашего развернутого бэкенда, например: `https://your-backend.vercel.app`

**Как добавить:**
1. Нажмите **"Add"** или **"Add Variable"**
2. Введите имя: `VITE_API_BASE_URL`
3. Введите значение (ваш URL бэкенда)
4. Выберите все окружения: Production, Preview, Development
5. Нажмите **"Save"**

### Шаг 6: Развертывание
1. Нажмите **"Deploy"**
2. Дождитесь завершения сборки (обычно 1-3 минуты)
3. После успешного развертывания вы увидите ссылку на ваш сайт:
   - Например: `https://xtrix-frontend.vercel.app`

## 🖥️ Способ 2: Развертывание через Vercel CLI (альтернатива)

Если хотите развернуть прямо из командной строки:

### Шаг 1: Установка Vercel CLI
```powershell
npm install -g vercel
```

### Шаг 2: Вход
```powershell
vercel login
```
Откроется браузер для авторизации.

### Шаг 3: Переход в папку frontend
```powershell
cd frontend
```

### Шаг 4: Развертывание
```powershell
vercel
```

Следуйте инструкциям:
- **Set up and deploy?** → `Y`
- **Which scope?** → выберите ваш аккаунт
- **Link to existing project?** → `N` (для первого раза)
- **Project name?** → нажмите Enter (используется имя по умолчанию)
- **In which directory is your code located?** → `./` или `.`
- **Want to override the settings?** → `N`

### Шаг 5: Добавление переменных окружения
```powershell
vercel env add VITE_API_BASE_URL
```
Введите значение, когда попросит.

### Шаг 6: Продакшн деплой
```powershell
vercel --prod
```

## 🔧 Проблемы и решения

### Ошибка "Build failed"
- Проверьте, что `Root Directory` установлен в `frontend`
- Убедитесь, что все зависимости установлены (`npm install`)

### Ошибка подключения к API (Network Error)

**Симптомы:** При попытке логина или регистрации возникает "Network Error" или "Failed to fetch"

**Причины и решения:**

1. **Переменная `VITE_API_BASE_URL` не установлена:**
   - В Vercel перейдите в **Settings** → **Environment Variables**
   - Убедитесь, что есть переменная `VITE_API_BASE_URL`
   - Если её нет - добавьте (см. Шаг 5 в инструкции выше)
   - После добавления/изменения переменной нужно **переразвернуть проект**:
     - Перейдите в **Deployments**
     - Найдите последний деплой
     - Нажмите **"..."** → **"Redeploy"**

2. **Бэкенд недоступен:**
   - Если используете `localhost:8000` - это **не будет работать** на Vercel
   - Нужен реальный URL бэкенда (развернутый на Vercel, Heroku, Railway и т.д.)
   - Пример правильного URL: `https://your-backend.vercel.app` или `https://api.xtrix.com`

3. **CORS не настроен на бэкенде:**
   - На бэкенде нужно добавить домен Vercel в разрешенные CORS origins
   - Добавьте в `.env` бэкенда:
     ```
     CORS_ORIGINS=https://ваш-проект.vercel.app,https://ваш-проект-*.vercel.app
     ENVIRONMENT=production
     ```
   - Или если бэкенд на Vercel - добавьте эти переменные в настройках бэкенда
   - После изменения CORS настройки перезапустите бэкенд

4. **Проверка в браузере:**
   - Откройте консоль браузера (F12)
   - Посмотрите на вкладку **Network** при попытке логина
   - Проверьте, какой URL используется для запроса
   - Убедитесь, что запрос идет на правильный адрес бэкенда

### Сайт открывается, но белый экран
- Откройте консоль браузера (F12) и проверьте ошибки
- Проверьте, что `base` в `vite.config.ts` установлен в `/`

## 🔗 Как поделиться проектом после деплоя

### 1. Получить ссылку на проект

После успешного развертывания вы увидите:

✅ **Deployment successful!**

Ваш проект будет доступен по адресу:
- **Production URL**: `https://ваш-проект.vercel.app`
- Пример: `https://xtrix-frontend.vercel.app`

**Где найти ссылку:**
- На главной странице проекта в Vercel (после деплоя)
- В разделе "Deployments" → нажмите на последний деплой → скопируйте URL
- Или просто скопируйте URL из адресной строки после деплоя

### 2. Поделиться ссылкой

**Просто скопируйте и отправьте ссылку:**
```
https://ваш-проект.vercel.app
```

**Можно поделиться:**
- Через мессенджер (Telegram, WhatsApp и т.д.)
- По email
- В документе/презентации
- Через GitHub (добавить в README.md)

### 3. Проверьте перед отправкой

**Обязательно проверьте:**
1. ✅ Сайт открывается и работает
2. ✅ Логин работает (если есть бэкенд)
3. ✅ Все функции работают правильно
4. ✅ Бэкенд доступен (если используется отдельный URL)

### 4. Настройка кастомного домена (опционально)

Если хотите более красивый адрес:

1. В Vercel перейдите в **Settings** → **Domains**
2. Нажмите **"Add Domain"**
3. Введите желаемый домен (например: `xtrix.com`)
4. Следуйте инструкциям для настройки DNS

**Или используйте бесплатный поддомен Vercel:**
- Домен по умолчанию уже красивый: `ваш-проект.vercel.app`
- Можно использовать его для демонстрации

### 5. Добавить ссылку в GitHub (опционально)

Можно добавить ссылку в README вашего репозитория:

```markdown
## 🌐 Демо

**Доступно по адресу:** [https://ваш-проект.vercel.app](https://ваш-проект.vercel.app)
```

### 6. Важные моменты

⚠️ **Обратите внимание:**
- **Ссылка работает сразу** после успешного деплоя
- **Каждый новый деплой** обновляет проект автоматически
- **Предпросмотр версии** доступен для каждого коммита (Preview Deployments)
- **Production** - это основная версия, которая всегда доступна

## 📝 Важно

- **Для продакшна** используйте реальный URL бэкенда (не `localhost`)
- **Если бэкенд тоже на Vercel**, добавьте его URL в переменные окружения
- **CORS** на бэкенде должен разрешать запросы с вашего Vercel домена
- **Перед отправкой** убедитесь, что проект полностью работает
