# 📋 КАТЕГОРИЗАЦИЯ УСЛУГ И ВАЛИДАЦИЯ - КРАТКОЕ ОБЪЯСНЕНИЕ

## 🎯 Как работает категоризация услуг

### Что это?
Каждая услуга теперь может иметь категорию: `beauty`, `wellness`, или `healthcare`.

### Автоматическое определение категории
1. При создании услуги, если категория не указана вручную:
   - Система смотрит на тип специалиста (`specialist_type` в профиле специалиста)
   - Автоматически определяет категорию на основе маппинга типов:
     - Массажист, косметолог, барбер → `beauty`
     - Физиотерапевт, нутрициолог, психолог → `wellness`
     - Врач, стоматолог, терапевт → `healthcare`

### Пример:
```
Специалист: тип = "dentist" (стоматолог)
Создается услуга "Чистка зубов" без указания категории
→ Система автоматически устанавливает category = "healthcare"
```

### Ручная установка категории
Можно указать категорию вручную при создании услуги через API:
```json
{
  "name": "Массаж",
  "specialist_id": 1,
  "category": "beauty",  // можно указать вручную
  "price": 1000,
  "duration_minutes": 60
}
```

## 🔒 Как работает валидация для healthcare специалистов

### Когда срабатывает?
Валидация проверяет обязательные поля только при создании нового клиента для специалистов с категорией `healthcare`.

### Что проверяется?
Для healthcare специалистов (врач, стоматолог, терапевт и т.д.) при создании нового клиента проверяется:

1. Существует ли `MedicalProfile` для клиента
2. Заполнены ли обязательные поля:
   - `allergies` (аллергии)
   - `chronic_diseases` (хронические заболевания)

### Что происходит при ошибке?
Если поля не заполнены, система вернет ошибку:
```
"For healthcare specialists, medical profile with required fields (allergies, chronic_diseases) must be created."
```

### Важно:
- Валидация работает только при создании нового клиента
- Для существующих клиентов ошибка не блокирует доступ (только предупреждение в логах)
- Для beauty и wellness специалистов валидация не требуется

### Пример работы:

**Сценарий 1: Создание клиента от врача (healthcare)**
```
1. Создаете клиента через API
2. Система проверяет: есть ли MedicalProfile?
3. Если нет → ошибка
4. Если есть, проверяет: заполнены ли allergies и chronic_diseases?
5. Если нет → ошибка
6. Если да → клиент создается успешно
```

**Сценарий 2: Создание клиента от массажиста (beauty)**
```
1. Создаете клиента через API
2. Валидация не проверяется (beauty специалист)
3. Клиент создается успешно
```

## 📝 Как использовать на практике

### 1. Создание услуги с автоматической категорией
Просто создайте услугу без указания категории - система определит её автоматически из типа специалиста.

### 2. Создание клиента от healthcare специалиста
**Вариант A: Сначала создайте MedicalProfile**
```json
POST /clients/
{
  "full_name": "Иван Иванов",
  "contact_phone": "+1234567890"
}
// Создайте MedicalProfile отдельно с allergies и chronic_diseases
```

**Вариант B: Создайте клиента с медицинскими данными сразу**
В будущем можно добавить endpoint, который создает клиента и MedicalProfile вместе.

### 3. Для beauty/wellness специалистов
Работает как раньше - никаких дополнительных проверок, просто создаете клиента.

---

## ⚠️ Важные замечания

1. **Категория услуги опциональна** - если не указана, определяется автоматически
2. **Валидация не блокирует работу** для существующих клиентов
3. **Для beauty/wellness специалистов** никаких ограничений нет
4. **Для админов** валидация тоже работает, если админ создает клиента от healthcare специалиста

## 🔍 Проверка в системе

### Как проверить категорию услуги:
```
GET /services/
→ Смотрите поле "category" в ответе
```

### Как проверить тип специалиста:
```
GET /users/me
→ Смотрите поле "specialist_type"
```

### Как проверить категорию специалиста:
```
GET /specialist-profiles/me
→ Смотрите поле "specialist_category"
```
