## Шаг 3: ⚠️ ВАЖНО - Ограничения Sandbox домена

Mailgun sandbox домен (тестовый) позволяет отправлять email **ТОЛЬКО на адреса, которые вы вручную добавили и подтвердили**.

### ❌ Проблема:
- **Нельзя отправить email новому пользователю автоматически**
- Нужно **вручную добавлять каждый email** перед отправкой
- Это **только для тестирования**, не для продакшена!

### Как верифицировать email для тестирования:

1. Откройте Mailgun Dashboard: https://app.mailgun.com
2. Перейдите в раздел **Sending** → **Domain Settings**
3. Выберите ваш sandbox domain
4. Перейдите на вкладку **Authorized Recipients**
5. Нажмите **Add New Recipient**
6. Введите email адрес, на который хотите получать письма
7. Mailgun отправит письмо с подтверждением на этот адрес
8. Перейдите по ссылке в письме для подтверждения

**ВНИМАНИЕ**: Без верификации email адресов, письма не будут отправляться!

### ✅ Решение для продакшена: Верифицировать свой домен

Чтобы отправлять на **любые** email адреса (включая новых пользователей):

1. В Mailgun Dashboard перейдите в **Sending** → **Domains**
2. Нажмите **Add New Domain**
3. Введите свой домен (например, `xtrix.com`)
4. Настройте DNS записи:
   - **TXT** запись для верификации
   - **MX** записи (опционально)
   - **CNAME** для отслеживания открытий
5. После верификации можно отправлять на **любые** адреса!

**Преимущества:**
- ✅ Можно отправлять на любые email адреса автоматически
- ✅ Письма идут от вашего домена (профессионально)
- ✅ Первые 5,000 писем/месяц бесплатно

## Troubleshooting

### Письма не приходят:
1. Проверьте, что email адрес верифицирован в Mailgun
2. Проверьте логи Railway на наличие ошибок
3. Проверьте, что переменные `MAILGUN_API_KEY` и `MAILGUN_DOMAIN` правильно установлены

### Ошибка "Forbidden" или "401":
- Проверьте правильность `MAILGUN_API_KEY`

### Ошибка "Domain not found":
- Проверьте правильность `MAILGUN_DOMAIN`

## Альтернатива: SMTP через Mailgun

Если хотите использовать SMTP вместо API:

1. В Mailgun Dashboard перейдите в **Sending** → **Domain Settings**
2. Выберите ваш domain
3. Перейдите на вкладку **SMTP credentials**
4. Создайте SMTP user и получите пароль
5. Используйте эти настройки:
   - `SMTP_HOST`: `smtp.mailgun.org`
   - `SMTP_PORT`: `587`
   - `SMTP_USER`: созданный SMTP user
   - `SMTP_PASSWORD`: пароль от SMTP user
   - `SMTP_FROM`: `noreply@sandbox979886e4a4264363accda32b9801bb27.mailgun.org`

Примечание: Код автоматически использует Mailgun API, если настроены `MAILGUN_API_KEY` и `MAILGUN_DOMAIN`. Если эти переменные не настроены, он попытается использовать SMTP.

## Что будет, если Mailgun не настроен?

Если переменные `MAILGUN_API_KEY` и `MAILGUN_DOMAIN` не установлены:

- ✅ Код восстановления будет сгенерирован
- ✅ Код будет сохранен в базе данных
- ❌ Email не будет отправлен
- ✅ Код будет залогирован в Railway (для тестирования)
- ⚠️ Пользователь не получит email (только для разработки!)

### Где посмотреть код в логах Railway:

1. Откройте Railway Dashboard
2. Выберите ваш сервис
3. Перейдите в раздел **Deployments** → **View Logs**
4. Найдите строку вида: `Password reset code for email@example.com: 123456`
